# ADR-016: Demo style switching via live-binding shims (no reload)

The web demo's style picker (Preview card header on item pages) switches which resolved tree renders — instantly, with no page reload. Because styles are resolved module graphs — the same sources with different class strings baked in — switching means rebinding which tree's exports the demo reads: `scripts/generate-style-shims.mjs` (run by every web pre-hook, after resolve-styles) emits per-item shims into gitignored `src/generated/registry/{ui,lib,blocks}/` that declare every value export as an ES-module live binding (`export let X`, initialized from the tree active at module-eval time) and reassign them when `setActiveStyle()` (`src/active-style.ts`) fires the registered reloaders. The `SelectedRegistryStyle` update calls `setActiveStyle` synchronously — persistence to `localStorage` (`foldcn-style`) lives inside it — and the foldkit re-render then picks up the new classes; demo state (open accordions, dialog state, toasts) survives the switch. Consumers read the bindings inside view functions, so nothing bakes at module scope (the only module-scope calls are stateful submodel factories like `Menu.create()`, whose schemas are style-independent). Blocks compose components via the `@/components/ui/*` alias; in the demo those imports resolve to the shims (vite aliases), so a block from one tree composes the active style's components and follows switches — never a fixed tree. Boot with a stored non-default style still client-renders (`Runtime.run` instead of `Runtime.hydrate`) because prerendered HTML is always default-styled; after that first load, everything is live. The generator asserts export-name parity across trees and emits type aliases for value+type exports (Schema structs like `Model`/`Message` need both facets for namespace consumers) while pure types — including generic `*Config` types — re-export via `export type { … } from` to keep type parameters intact. Tailwind scans all nine trees (`styles.css` `@source` lines) so every style's utilities exist. (Design note: shadcn's own site solves the same problem with per-style routes and iframe previews — `/view/[style]/[name]` — where switching is iframe navigation; foldkit's re-render-on-message architecture makes the direct rebinding approach both possible and instant.)
